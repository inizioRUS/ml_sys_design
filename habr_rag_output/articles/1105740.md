# Исследование: во сколько обходится AI‑разработка сайта в зависимости от используемых JavaScript‑фреймворков

Разработчик Нолан Лоусон (Nolan Lawson) [сравнил](https://nolanlawson.com/2026/10/28/the-ai-cost-of-javascript-frameworks/), сколько денег и времени требуется нейросетям для разработки одного веб‑приложения на разных JavaScript‑фреймворках. В тестах самым дорогим вариантом оказался Angular, а самым дешёвым — связка Hono и htmx. Разница в медианной стоимости составила почти два раза.

В эксперименте Лоусон поручил Claude Code с моделью Opus 5.5 и высоким уровнем рассуждения разработать каталог покемонов с поиском, фильтрами и реальными данными из PokéAPI. Разработчик проверил 12 вариантов, включая JavaScript без UI‑фреймворков, и запустил каждый вариант по пять раз. У каждого агента было одинаковое задание и функциональные тесты.

По медианным результатам пяти запусков быстрее всего агент справился с Astro — за 8,2 минуты. Самой дешёвой связкой оказалась Hono с htmx: 2,67 доллара за приложение при времени 8,6 минуты. Худшим вариантом одновременно по двум показателям оказался Angular: 17,2 минуты и 4,97 доллара. Это примерно в два раза дольше и дороже самого быстрого и самого дешёвого вариантов.

Версия на чистом JavaScript без UI‑фреймворков не стала самой быстрой или экономичной. Агент потратил на разработку 2,98 доллара, а заняло это 10,1 минуту. Вариант с Astro или связкой Hono и htmx опередить не удалось.

Меньше всего токенов потребовалось Nuxt — 3,85 млн, больше всего Angular — 9,76 млн, примерно в 2,5 раза больше. Основную часть потребления составило повторное чтение кешированного контекста.

Разница в оценках полученных веб‑приложений оказалась небольшой. Медианные показатели производительности Lighthouse составили 97–100 баллов, а доступности — 100.
