# Anthropic выпустила гайд — какую модель выбирать для конкретных задач

Anthropic [выпустила](https://claude.dev/blog/which-claude-model-should-you-build-with/) гайд, в котором объяснено, какую именно ИИ-модель нужно выбирать для конкретных задач, так как самая мощная система не всегда оказывается лучшим вариантом в определённых случаях. Гайд поможет сэкономить на токенах и подобрать модель эффективно под каждую задачу. Можно с помощью этого учебного материала сэкономить, практически не теряя в качестве:

- Opus 5.5 — универсальный вариант. Именно с неё Anthropic советует начинать большинство задач.
- Haiku 5.5 — самая быстрая и дешёвая. Подходит для классификации, и простых задач и субагентов, которые читают логи.
- Sonnet 5.5 — для повседневной работы, исправления багов, создания документов и общения.
- Fable 5.2 — самая мощная модель линейки для масштабных проектов, сложных исследований и научных расчётов.

Внутренний субагент Explore теперь работает на основной модели, а раньше работал на простенькой Haiku — поэтому пользователи могут попусту сжигать лимиты Fable 5.2.

Чтобы Claude использовал руководство сам и не тратил токены зря, выдайте ему этот промпт:

> Настрой мой Claude Code: дешёвые субагенты для рутины, основная модель для решений. Встроенный Explore теперь работает на модели сессии, а не на Haiku, поэтому поиск подорожал.
>
> 1. Покажи версию Claude Code, провайдера, содержимое ~/.claude/agents/ и .claude/agents/, значения CLAUDE\_CODE\_SUBAGENT\_MODEL и ANTHROPIC\_DEFAULT\_HAIKU\_MODEL. Спроси, ставить агентов глобально или в проект. Ничего не перезаписывай без моего «да».
>
> 2. Алиас haiku означает Haiku 5.5 только на Anthropic API с Claude Code v2.1.293+. На Bedrock, Google Cloud, Foundry и Claude Platform on AWS он ведёт на Haiku 4.5: предложи задать ANTHROPIC\_DEFAULT\_HAIKU\_MODEL на Haiku 5.5, если она там есть.
>
> 3. Создай агентов с model: haiku и tools: Read, Grep, Glob, Bash, без права редактировать файлы:  
> - Explore (перекроет встроенный): возвращает путь:строка и строку пояснения, без файлов целиком; если не уверен, так и говорит.  
> - log-reader: по логам и выводу сборки сообщает, что упало, первую причину, путь:строка и точный текст ошибки.  
> - test-runner: запускает тесты или сборку и сообщает «прошло / упало» со списком падений.  
> CLAUDE\_CODE\_SUBAGENT\_MODEL не задавай: она удешевит и Plan с general-purpose.
>
> 4. Добавь в CLAUDE.md (спроси, в какой):  
> - Поиск, длинные логи и тесты отдавай Explore, log-reader, test-runner. Дела в 1–3 вызова инструментов делай сам.  
> - Правки, решения и ревью делай сам. Вывод субагента перед правкой проверяй по указанному месту.  
> - Если не выходит: проверь себя тестами, потом подними effort на уровень, и только потом бери модель сильнее.  
> - Перед сменой модели делай /compact.
>
> 5. Сам настройки не меняй, покажи рекомендацию: по умолчанию Opus 5.5, effort medium (high для трудного); Sonnet 5.5 для задач по чёткой спецификации и документов; Fable 5.2 для крупных миграций, архитектуры и долгих автономных прогонов. Сначала меняй effort, потом модель.
>
> 6. Проверь в /agents, что Explore работает на Haiku, сделай пробный поиск и отчитайся: что создано (с путями), что решать мне, что не проверено.
