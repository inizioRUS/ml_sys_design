# Как посчитать трафик из нейросетей, который уходит в прямые заходы Метрики и GA4

Переход из ответа ChatGPT в Метрике часто выглядит как визит без источника. У меня в Метрике есть отдельный сегмент AI Traffic для визитов из нейросетей, и стандартный отчёт по источникам видит из них только те, где нейросеть сама передала метку или реферер, то есть адрес страницы, с которой человек пришёл. Остальной трафик из нейросетей оседает в прямых заходах, и там его, похоже, меньше, чем я ожидал: [Tenpoint Labs](https://tenpointlabs.com/research/ai-direct-traffic) оценила скрытую долю ИИ максимум в 6,3% прямых заходов. Поэтому стандартного отчёта мало: точную часть даёт свой сегмент по рефереру и метке, а скрытую придётся оценивать по признакам визита.

### Как Метрика решает, откуда пришёл визит

Метрика определяет источник по меткам и рефереру: метку она ищет только в первом просмотре визита, а если её там нет, смотрит на реферер ([справка Метрики](https://yandex.ru/support/metrica/ru/general/sources-tracking)). Реферер браузер передаёт в HTTP-заголовке Referer. Если нет ни метки, ни реферера, визит записывается в прямые заходы. Такой трафик называют тёмным: визит в аналитике есть, а источника у него нет.

В прямые заходы попадают переходы из мобильных приложений с WebView, то есть с мини-браузером внутри приложения, из мессенджеров без метки, из ChatGPT и из чата Алисы. Это я разбирал [в статье про сегмент по домену реферера в Метрике](https://habr.com/ru/articles/1058796/). Реферер может срезать и сама страница, с которой человек уходит: правило referrer-policy задаёт, отдаёт ли браузер её адрес при переходе.

### Что известно о передаче источника из браузера и приложений нейросетей

Подтверждённые данные есть только по ChatGPT и Алисе AI, и ни у одной из них по источнику нельзя посчитать все переходы. По GigaChat, Perplexity и DeepSeek подтверждения нет ни для веба, ни для приложения.

| Нейросеть | В вебе | В приложении |
| --- | --- | --- |
| ChatGPT | метка utm\_source=chatgpt.com есть у части ссылок; по Seer Interactive, даже ссылка в блоке источников метку не гарантирует | приложения ChatGPT могут терять реферер, допускает Tenpoint Labs; прямого подтверждения нет |
| Алиса AI | ответ в поиске приходит с реферером yandex.ru/search, как обычный клик по выдаче | подтверждения нет |
| GigaChat | подтверждения нет | подтверждения нет |
| Perplexity | подтверждения нет | подтверждения нет |
| DeepSeek | есть в списке канала AI Assistant в GA4, который определяется по рефереру; своего теста нет | подтверждения нет |

### Как собрать в Метрике сегмент для трафика из нейросетей по домену источника и utm-метке

AI-трафик в Метрике выделяет сегмент с двумя условиями через ИЛИ: домен реферера и значение utm\_source, потому что ИИ-визит может принести любое из двух. Регулярки в Метрике пишутся по [синтаксису RE2](https://yandex.ru/support/metrica/ru/general/regexp), а значения меток [Метрика различает по регистру](https://yandex.ru/support/metrica/ru/general/source-tags.html), поэтому в условии по метке стоит флаг (?i). В Метрике создайте сегмент по визитам и добавьте в него два условия: первое по домену реферера, второе по значению utm\_source, и свяжите их через ИЛИ. У каждого условия выберите проверку по регулярному выражению и вставьте в поле значения ниже, каждое в своё условие:

```
Условие по домену реферера:
^(.*\.)?(chatgpt\.com|chat\.openai\.com|perplexity\.ai|gemini\.google\.com|copilot\.microsoft\.com|claude\.ai|deepseek\.com|grok\.com)$

Условие по utm_source:
(?i)^(chatgpt(\.com)?|perplexity(\.ai)?|gemini|copilot|deepseek|claude|grok)$
```

Сервисы в списке взяты из справки GA4 и исследования Tenpoint Labs, домены — адреса этих сервисов. Из значений метки источники подтверждают только chatgpt.com, остальные написания я добавил как вероятные: сверьте их с отчётом по меткам своего счётчика. Домен yandex.ru в список не идёт: у ответа Алисы в поиске реферер тот же, что у органики, и сегмент заберёт всю выдачу. GigaChat тоже не вошёл, пока не подтверждено, какой реферер он отдаёт.

### Как выделить ИИ-визиты в GA4 собственной группой каналов

В GA4 есть [штатный канал AI Assistant](https://support.google.com/analytics/answer/9756891) для ChatGPT, Gemini, DeepSeek, Copilot и Grok; AI Overviews и AI Mode в него не входят. Google относит визит к этому каналу по рефереру: если реферер совпал со списком ИИ-ассистентов, medium получает значение ai-assistant, а визит без реферера в канал не попадёт. По определению Google, Direct — это заход по сохранённой ссылке или вводу адреса, но ИИ-визиты без реферера оказываются как раз там.

Своя группа каналов нужна для сервисов вне штатного списка. Условие канала: источник сеанса соответствует регулярке

```
^(.*\.)?(chatgpt\.com|chat\.openai\.com|perplexity\.ai|gemini\.google\.com|copilot\.microsoft\.com|claude\.ai|deepseek\.com|grok\.com)$
```

Если в отчёте встречаются метки без домена, например utm\_source=perplexity, допишите их в ту же скобку через вертикальную черту. В [справке по собственным группам каналов](https://support.google.com/analytics/answer/13051316?hl=en) Google просит поставить ИИ-канал в списке выше Referrals.

### Как оценить, какая часть прямых заходов пришла из нейросетей

Оценить скрытую долю можно только по признакам визита. Визит с ИИ-меткой GA4 и так относит к ИИ-источнику: Tenpoint Labs проверила 489 920 прямых сессий на 10 сайтах и не нашла ни одной с меткой ChatGPT, Perplexity, Gemini, Copilot или Claude. Остаются визиты без метки и реферера. Tenpoint взяла самое щедрое допущение, что весь вовлечённый прямой заход на глубокие страницы приходит из ИИ, и даже так получила всего 6,3% прямых заходов на 6 сайтах, где ИИ-визитов хватило для расчёта. Для сравнения, Ramp, на которую ссылается Tenpoint, называет 30–40%.

Сегмент для Метрики ниже строится на том же допущении. Пороги в нём предлагаю я, их стоит оспорить:

```
ym:s:lastTrafficSource=='direct'
AND ym:s:startURL!~'^https?://[^/]+/?(\?.*)?$'
AND ym:s:startURL!~'/(blog|promo|landing)/'
AND ym:s:bounce=='No'
AND (ym:s:pageViews>=2 OR ym:s:visitDuration>=30)
```

- вторая строка отсекает вход на главную; регулярка в Метрике применяется к полному URL с протоколом и доменом, поэтому она начинается с https?://;
- третья отсекает разделы, куда вы сами ведёте рекламу и поисковый трафик, список замените на свой;
- последние две оставляют только вовлечённые визиты: без отказа и с двумя просмотрами или 30 секундами на сайте.

Без порога вовлечённости сегмент наберёт мусора. На 6 из 8 сайтов Tenpoint прямые заходы на глубокие страницы вовлекались заметно реже, чем ИИ-рефералы и органика. По выводу авторов, такие визиты больше похожи на ботов и превью ссылок. Глубокую страницу без SEO и рекламы, но с прямым трафиком я в прошлой статье называл подозрительным паттерном: проверять её стоит, но заход из нейросети она сама по себе не доказывает.

Доля считается так: визиты сегмента делим на все прямые заходы за тот же период. Вышло заметно выше 6,3% — сначала стоит поискать роботов и превью ссылок.

Точную часть дают реферер и метка, оценка появляется только после фильтров по прямым заходам.

### Где подсчёт трафика из нейросетей врёт и как подать итоговую цифру

Подсчёт врёт в четырёх местах, и пороги сегмента их не закрывают.

- Алиса AI. Её ответ в поиске приходит с yandex.ru/search и растворяется в органике, а чат Алисы уходит в прямые заходы и может попасть только в оценку.
- Всплеск прямых заходов после публикации, которую цитируют нейросети. Это корреляция: рост мог дать репост в закрытом чате или рассылка. Исследование Tenpoint не подтвердило, что всплески прямых заходов связаны с переходами из нейросетей. Поэтому всплеска в порогах нет.
- Устройство. Прямые заходы на глубокие страницы у Tenpoint шли в основном с десктопа, как и ИИ-рефералы, хотя приложения ChatGPT могут терять реферер.
- Малые числа. Единственный слабый сигнал у Tenpoint, совпадение по неделям вовлечённых прямых заходов на главную с ИИ-рефералами (r = 0,45 на одном сайте), держался примерно на пяти ИИ-визитах в неделю и поправку не прошёл.

Стандартный отчёт по источникам занижает трафик из нейросетей: он учитывает только визиты, где нейросеть сама передала реферер или метку. Подсчёт, которому можно верить, складывается из двух частей: точной, которая видна по рефереру и utm, и оценочной, которую выделяют из прямых заходов по признакам визита. Вторую часть нужно подавать как оценку с ясными допущениями: порог в два просмотра или 30 секунд, исключённые разделы, боты и превью ссылок, которые сегмент не отсекает. В отчёте это две строки: точная часть и оценка: число прямых визитов, подходящих под признаки сегмента.

Показываем не одно число, а вилку: от точной части слева до точной плюс оценка справа.

Интересно, у кого скрытая доля вышла заметно выше 6,3% и как вы отсеяли ботов и превью ссылок.
