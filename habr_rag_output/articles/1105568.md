## Введение и описание

Несколько лет назад с целью изучения языка JavaScript мной была выбрана тема, связанная с симуляцией физических явлений. Поскольку основной задачей было как можно более полное понимание самого языка программирования, было решено отказаться от использования библиотек и фреймворков. Сам проект включал в себя симуляции физических приборов, механических процессов и экспериментов с жидкостями. Подобные явления рассматривались многими на лабораторных работах в средней школе.

Старый программный код можно найти по [ссылке](https://github.com/practicalDeveloper/JavaScript_Physics). Предыдущая статья доступна [здесь](https://web.archive.org/web/20230522061226if_/https://www.codeproject.com/Articles/5280715/Physical-Simulations-in-Vanilla-JS). Также доступен работающий сайт со старыми демонстрациями по этому [адресу](https://practicaldeveloper.github.io/JavaScript_Physics/) .

Скриншот предыдущего проекта

Позже я вернулся к развитию своего проекта. Моей целью было добавление новых возможностей, новых симуляций, изменение структуры программы с учетом новых возможностей JavaScript, адаптация под смартфоны, а также улучшение интерфейса. Для модернизации проекта и добавления новых функций требовалось не только сохранить поведение моделей, но и улучшить программную архитектуру.

Подобные изменения при работе в одиночку занимают массу времени. В подобной ситуации пригодились инструменты искусственного интеллекта, которые смогли помочь отрефакторить код и модернизировать проект за гораздо более короткий промежуток времени.

В данной статье рассказано, как менялся проект, как использовался ИИ ChatGPT и Cursor и с какими проблемами пришлось столкнуться.

### Исходное состояние

Центральной страницей проекта является `index.html`

В предыдущей версии `index.html` подключал объекты JS - кода и скрипты напрямую через `<script src>` без использования модулей.

Общая схема старого проекта

В старой версии проекта для организации архитектуры использовался классический *модульный паттерн*, который  разбивал js-код на объекты `const` и группировал функции, другие элементы по назначению.

Логика экспериментов по необходимой физической теме осуществлялась в следующих объектах: `appliancesDemo`*,* `archimedesPrincipleDemo`*,* `forcesbyAngleDemo`*,* `pendulumDemo` (например, `const archimedesPrincipleDemo = { ... }`, `const pendulumDemo = { ... }` и. т. д.). Внутри этих const-объектов происходила обработка параметров, поступающих от пользователя, последующая компоновка приборов, группировка функций и отрисовка  сцены на холсте canvas.

За группировку логики по перетаскиванию по экрану и группировку функций общего назначения отвечали объекты: `dragRendering`*,* `contextLayout`.

При таком подходе требуется подключение используемых js-файлов в HTML-коде через `script src`*.* Например, приходилось подключать все используемые js-файлы в центральном месте `index.html`*,* чтотребовало соблюдения порядка последовательности файлов:

```
    <script src="./js/appMethods.js"></script>

    <script src="./js/dragging.js"></script>

```

### Переход от модульного паттерна к использованию классов

Предыдущий подход разбиения архитектуры на блоки `const`, с сгруппированным функционалом является устаревшим. Это создавало неудобства при поддержке,  при внесении изменений или расширении проекта. Кроме того, при применении объектов `const` неудобно создавать приватные методы, поля для скрытия данных от внешнего использования.

Для визуализации и создания физических приборов (динамометров, линеек, пружин и.т.д.), которые могут применяться многократно, но с разными параметрами использовался метод *функций – конструкторов***.** Например, абстрактное устройство для визуализации циферблата со стрелкой без чисел:

```
function Appliance(options = {}) {
 // Значения по умолчанию 
 Object.assign(this, {
…
  }, options);
…
}
```

Прибор для измерения силы — динамометр — строился на основании этого абстрактного устройства с добавлением новых свойств. Для этого применялось *прототипное наследование*. Пример создания стрелочного динамометра и наследование от `Appliance`:

```
function Dynamometer(options) {
  Appliance.call(this, options); // вызов базового конструктора 
 ...
}
Dynamometer.prototype = Object.create(Appliance.prototype); // организация цепочки прототипов
Dynamometer.prototype.constructor = Dynamometer;

Dynamometer.prototype = {
  draw: function () { ... );
}
```

В современном JavaScript чаще используется подход использования модулей (`import/export`). Это позволяет экспортировать классы, функции для использования в других JS – файлах. В классах можно организовать код более структурировано и понятно, организовать поддержку приватных полей с помощью встроенного синтаксиса. Для использования экспортированных объектов достаточно прописать , что происходит их импорт на уровне JavaScript кода.

Иерархия наследования при использовании классов решается более понятным способом, чем с использованием функций-конструкторов. Для этого применяется ключевое слово `extends.` А чтобы получить доступ к конструктору родителя и его свойствам в классах используется простое использование конструкции `super`. К примеру, создание объекта `Appliance` и его наследника`Dynamometer`*,* которые были описаны выше,  реализуется следующим образом:

```
export class Appliance {
  #fieldsAppl; // приватные свойства
  constructor(options = {}) {
    // Свойства значения по умолчанию
    Object.assign(
      this,
      {
        centerX: 0,
        centerY: 0,
        radius: 50,
      },
      options,
    );
  }
  ...
}

// Dynamometer наследует Appliance
export class Dynamometer extends Appliance {
  constructor(options = {}) {
    // наследование конструктора от Appliance
    super(options);
    // Свойства значения по умолчанию для Dynamometer
    Object.assign(
      this,
      {
        maxValue: 10,
      },
      options,
    );
  }
  ...
}
```

На этом этапе для решения задачи по переходу на `import/export`использовался *ChatGPT* вместе с *Cursor*. *Cursor* способен исследовать и переделать весь проект целиком.  Однако такой объем изменений сложно будет отследить и позже переработать самостоятельно. Поэтому сначала объекты переводились в классы постепенно через *ChatGPT*.

Первая проблема, которая возникает, — не получается сделать модульными и настроить *import/export* объектов в проекте поочередно. Например, для начала, переводится в класс, прописывается *export* объекта `Spring` (функционал для отображения пружины из файла *"*`Tools/spring.js`*"* ). Если использовать `Spring` внутри другого объекта, который не является модульным, например внутри файла `springDynamometer.js` *,* топроявляетсяошибка *“* *Cannot use import statement outside a module”.*

То есть нельзя сделать модульным `spring.js`, если `springDynamometer.js` подключается как обычный `<script src>`*.* Придется переводить все объекты проекта в классы для экспорта одновременно*. ChatGPT* навел на мысль, что для начала объект можно перевести в класс и при этом сохранить глобальные объекты через `window`. Иными словами сначала создается `class Spring`, после его описания прописывается `window.Spring = Spring`*.*При этом нет необходимости использовать `export` и ломать структуру проекта.

Такой подход позволил переписать постепенно все объекты из каталога `js/Tools` на классы и привязать к `window`. После этого все объекты, отвечающие за реализацию логики обработки демонстраций из папки`js/TopicsRender`*.*

Затем, используя *Cursor*, удалось завершить работу и добиться работающего функционала.

### Создание языковой локализации

Изначально сайт содержал строго закодированные в HTML текстовые значения надписей, заголовков меню, блочных элементов  на английском языке. Это усложняло расширение и внесение изменений в структуру HTML, например при смене языка веб-сайта.

Для разрешения возникшей проблемы также использовался *ChatGPT* одновременно с *Cursor*.

Чтобы собрать надписи в одном месте, потребовалось создать файлы ресурсов для разных языков.  В качестве файла ресурсов можно выбрать JSON-формат.  Однако *ChatGPT* подсказал, что более удобно использовать просто JavaScript-объекты без необходимости асинхронной загрузки JSON – данных.

Пример части файла `strings.ru.js`*:*

```
export default  {
    Title : "Физика",
    SubTitle : "Моделирование",
...
};
```

В HTML-коде элементам, которые должны содержать текст из файла ресурсов, должен присваиваться пользовательский атрибут `data-resource` (например, `<p data-resource="SubTitle"></p>`). Впоследствии JS-код находит через атрибут значение в JS-объекте. Например, ресурс `Panel.Title`*:*

```
import ru from "../resources/strings.ru.js";
const attribute = "data-resource";

document.querySelectorAll(`[${attribute}]`).forEach((elem) => {
    elem.innerHTML = ru.Panel.Title;
});
```

Итоговая функция, чтобы найти любое значение из файла ресурсов:

```
static get(key) {
    const parts = key.split(".");
    let result = Resources.currentLang;
    for (const part of parts) {
      result = result[part];

      if (result === undefined) {
        return key;
      }
    }
    return result;
}
```

Дальше через запрос к *Cursor* были присвоены атрибуты ресурсов во всем проекте и создана локализация.

### Избавление от setTimeout и переход на механизм requestAnimationFrame для создания анимаций

Демонстрации подразумевают наблюдение вживую за физическими явлениями и поведением приборов, что требует создание различных анимаций. Например, возможна анимация движения стрелки динамометра или сжатие/разжатие пружины.

В старой версии приложения уже было предусмотрено  использование анимаций с помощью общего механизма для всего проекта `setTimeout`.  Данная функция, как известно, выполняет  какую-либо другую функцию только один раз через заданный интервал времени. В предыдущем проекте использовался рекурсивный `setTimeout` с асинхронным вызовом через `async/await`.

Пример анимации стрелки динамометра через `setTimeout`:

```
const application = {
  timeout: (ms) => new Promise((resolve) => setTimeout(resolve, ms)),
}

...

setValue: async function (valuePointer = 0) {
    ...
    async function tick() {
      face(); // отрисовка циферблата
      ...
      // draws value pointer according to condition
      async function setTimer(condition) {
        if (condition) {
          value(currentValue);
          await application.timeout(1); // ожидание 1 мс
          return await tick();
        }
        else {
          redraw(valuePointer);
          value(valuePointer);
          return;
        }
      } 

      if (initValue <= valuePointer) {
        currentValue = application.roundTwoDigits(currentValue + rotateSpeed);
        return await setTimer(currentValue <= valuePointer);
      }
    ...

    } // tick

    return tick(); 
} // setValue
```

Если требовалась отмена анимации, могла применяться функция, которая  создавала `Promise`на основе `setTimeout`и возвращала объект:

```
timeoutPromise: (ms) => {
    let timer = 0;
    const promise = new Promise((resolve) => {
      timer = setTimeout(resolve, ms);
    });
    return { promise, timer };
}
...
let timeout = application.timeoutPromise(1);
if (this.cancelTimer == true) {
    clearTimeout(timeout.timer);
}
```

Такой предыдущий подход через `setTimeout`имеет ряд недостатков. Анимация получается не привязана к частоте обновления экрана. Это означает, что может возникнуть рассохранизация между тем, как код обновляется на основании таймера, и как отрисовываются кадры на экране монитора. Также скорость анимации может зависеть от браузера: к примеру, `setTimeout(1)` после нескольких вызовов вложенных таймеров может задерживаться до нескольких миллисекунд. Следовательно, такой механизм может использоваться для создания только простых задач по анимации.

Для реализации более плавного анимирования, без задержек и “дерганий”, в данном проекте было решено перейти  на современные возможности *JavaScript* посредством использования `requestAnimationFrame`.

Данный метод позволяет более эффективно реализовать анимацию и в качестве параметра принимает функцию (*callback*), которая вызовется перед следующим вызовом фрейма перерисовки. В отличие от `setTimeout()` и `setInterval()`*,* для`requestAnimationFrame` не требуется указыватьвремя, через которое запустится функция. Данный метод возвращает `requestID`*,* который служит для отмены анимации через `window.cancelAnimationFrame()`*.*

Самой простой идеей по переводу функции `setValue`, приведенной выше, к использованию описанного механизмаявляется применение `Promise`, внутри которого применяется `requestAnimationFrame`.  При достижении необходимых условий `Promise` возвращает результат и анимация завершается. Однако `requestAnimationFrame` строго привязывается  к частоте экрана, которая отличается на разных устройствах (на смартфонах, на компьютерах).

Например:

```
const tick = () => {
  currentValue += 1; // всегда прибавляем 1 за кадр
  requestAnimationFrame(tick);
};
```

Это означает, что на мониторе с частотой 60 Гц стрелка будет двигаться со скоростью 60 пикселей в секунду, а при частоте 100 Гц – 100 пикселей в секунду.

Во избежание этого *ChatGPT* предложил ввести некий коэффициент для гарантии того, что анимация будет длиться всегда одно и то же время, независимо от частоты экрана.

```

    ...
```

### Адаптация под смартфоны и различные разрешения экрана

В первоначальной версии веб-сайта адаптивный дизайн отсутствовал, и демонстрации отображались корректно только на компьютерных мониторах и ноутбуках. Сайт невозможно было использовать на экранах с маленьким разрешением, например на смартфонах. Чтобы корректно отображать физические демонстрации  на различных устройствах, потребовалось не только изменить CSS-дизайн, но и переработать JavaScript-код для создания масштабирования сцен с демонстрациями.

Компоновка элементов на странице реализована в виде таблицы через `CSS Grid Layout`. Это позволяет работать с раскладкой  в виде колонок и рядов. Сам *Grid* отображается в файле `index.html` , а его раскладка прописана в файле `main.css.`

#### Адаптивность JavaScript демонстраций

Другой проблемой сайта было то, что JavaScript-cцены с демонстрациями экспериментов всегда отображались без учета изменения размеров разрешения экрана и, соответственно, размеров холста с отображенными сценами. Размеры физических приборов, координаты сброса грузов, координаты анимаций — все это имело фиксированные величины и координаты.

Для подсчета коэффициента масштабирования, который применяется для того, чтобы объекты и демонстрации подстраивались под разные размеры экрана, можно использовать простую функцию:

```
static applyScale(scene) {
    const scaleX = scene.canvas.width / scene.baseWidth;
    const scaleY = scene.canvas.height / scene.baseHeight;
    scene.stageScale = Math.min(scaleX, scaleY);
    return scene.stageScale;
}
```

Впоследствии, применяя Cursor, удалось настроить все демонстрации на использование этого метода.

Первоначальный размер холста со сценой до применения масштабирования, определяется следующим образом:

```
static setBaseSize(scene, baseWidth, baseHeight) {
    scene.baseWidth = baseWidth;
    scene.baseHeight = baseHeight;
    scene.stageScale = 1;
}
```

При начальной загрузке (например, `init`) каждой сцены применяется `setBaseSize`. А при любом изменении размеров сцены уже высчитывается коэффициент масштабирования через `applyScale` и применяются размеры или настройки:

### Создание боковых, сворачивающихся панелей

На экранах с маленьким разрешением, например, на экранах смартфонов, область с демонстрациями занимает мало места и неудобна для применения . Было решено расширить это пространство за счет сворачивания/разворачивания боковых панелей (меню, параметры).

Отправной точкой является идея в том, чтобы сделать нажимаемыми узкие области между боковыми панелями и областью с холстом. В эти маленькие области необходимо добавить текстовые надписи  “>” и “<” (свернуть/развернуть). Курсор при наведении должен меняться, размер текста - тоже. После нажатия на эту область необходимая панель должна становиться узкой, а элементы на ней - скрываться.

Генерацией через *Cursor* данной задачи является на первый взгляд рабочее решение. Панели сворачиваются, в свернутом состоянии изменяется дизайн на уменьшенный размер панели с надписями “Меню” и “Параметры”.

Однако при тестировании в режиме смартфона выяснилось, что сами панели куда-то съезжают. Кроме того, генерация кода выдала сложные манипуляции с CSS-грид и много дублирующегося CSS-кода. Скрывающиеся панели начали превращаться в подобие всплывающих окон, у которых меняется z-index . ВJavaScript-коде прописалась сложная логика: необходимые контейнеры находились через  `getElementById`, к ним добавлялись *CSS-атрибуты* и классы. Нерабочие сворачивающиеся панели

Предложенное через ИИ решение оказалось громоздким и сложным в применении. Причем наиболее эффективной получается связка нескольких ИИ-инструментов, например *ChatGPT* и *Cursor*. *ChatGPT* можно использовать в качестве универсального помощника, который может подсказать общие идеи и рассказать теорию (например, по физическим процессам или по программированию).  Также после генерации этой информации *ChatGPT* может вырабатывать эффективные и подробно описанные запросы для *Cursor*, который видит всю структуру проекта целиком.
